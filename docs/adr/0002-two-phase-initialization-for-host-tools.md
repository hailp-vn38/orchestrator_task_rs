# Two-Phase Initialization (`prepare` then `start`) for HostTool Registration

`OrchestratorBuilder::build()` validates that every tool listed in an `AgentDefinition::allowed_tools` is already registered before producing an `Arc<Orchestrator>`, while `TaskManager` needs `Arc<Orchestrator>` handles to dispatch Tasks and build the dynamic Target Agent catalog for the Voice Agent. We split initialization into `TaskManager::prepare(config)` (which opens `tasks.db`, acquires the owner lock, and exposes `HostTool` adapters backed by an internal late-bound runtime handle) and `TaskManagerInit::start()` (which binds the built `Arc<Orchestrator>` flows, reconciles in-flight Tasks, and starts background workers). This breaks the circular startup dependency without weakening `OrchestratorBuilder`'s compile/startup tool validation.
